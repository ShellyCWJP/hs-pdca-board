# PDCA Board 要件定義書

## 1. 背景

高校の課題研究（情報）の授業では、生徒が毎回の授業の前後に PDCA を紙で記録している。
授業前に「本日の目標・予定」（Plan）を書き、授業後に「実施内容・得られた結果」（Do）と「振り返り・次回の課題」（Check/Act）を書く。
終業後、教員がアドバイスを書き添える。

紙での運用には二つの問題がある。
一つは、当初立てた Plan と Do が 1 対 1 で対応づけられず、何が達成できて何ができなかったかが曖昧になること。
もう一つは、授業回を重ねる中で Plan に対する達成率がどう変わったかを振り返る手段がないことである。

本アプリケーションはこの二つを解決する。
同時に、授業の中で「課題を見つけ、アプリ開発によって解決を提案する」流れを生徒に見せるためのサンプルとして用いる。
そのため、機能は最小限にとどめる。

## 2. 目的

- Plan の各項目に対して Do を 1 対 1 で記録し、項目ごとの達成状態を残す。
- 授業回ごとの達成率を保存し、推移をグラフで確認できるようにする。
- 教員が生徒ごとの記録を一覧し、フィードバックを投稿できるようにする。

## 3. 利用者

| 役割 | 人数 | 主な操作 |
| --- | --- | --- |
| 教員 | 1 名 | 生徒登録、授業回作成、記録の閲覧、フィードバック投稿 |
| 生徒 | 1 クラス分（数十名） | Plan 登録、Do 記録、Check/Act 入力、自分の推移閲覧 |

クラスや年度の概念は持たない。
教員は 1 名、クラスは 1 つとして扱う。

## 4. 用語

- **授業回**：教員が事前に作成する 1 コマの授業。回番号と日付を持つ。
- **PDCA レコード**：ある授業回における、ある生徒 1 人分の記録。Plan、Do、Check/Act、教員フィードバックを含む。
- **Plan 項目**：その授業回で生徒が達成しようとする個々の目標。1 レコードに複数持てる。
- **Do**：Plan 項目ごとの実施内容と達成状態。Plan 項目に紐づかない追加の Do も自由記述で残せる。
- **達成状態**：Plan 項目ごとに「達成」「一部達成」「未達成」の 3 段階で記録する。
- **達成率**：1 レコード内の Plan 項目の達成状態から算出する 0〜100% の値。

## 5. 機能要件

### 5.1 認証

- 教員・生徒ともに Email とパスワードでログインする。
- 生徒アカウントは教員が生徒管理画面で作成し、初期パスワードを設定して生徒に手渡す。
- 教員アカウントはシードスクリプトで作成する。画面からは作成しない。
- 生徒は自分のパスワードを変更できる。
- パスワードリセットのメール送信は行わない。忘れた場合は教員が再設定する。

### 5.2 教員機能

- **ダッシュボード**
  - 直近の授業回について、生徒ごとに Plan・Do・Check/Act・フィードバックの有無を一覧する。
  - 授業回ごとのクラス平均達成率を折れ線グラフで表示する。
- **生徒管理**
  - 生徒の追加、氏名・Email の変更、パスワード再設定、削除ができる。
  - 削除した生徒の PDCA レコードも削除する。
- **授業回管理**
  - 授業回の追加（回番号・日付）、変更、削除ができる。
  - レコードが存在する授業回は削除できない。
- **記録一覧とフィードバック**
  - 授業回を選び、生徒ごとの PDCA レコードを閲覧する。
  - レコードごとにフィードバック（アドバイスのテキスト）を投稿・修正できる。
  - 主体性評価などの数値評価は持たない。

### 5.3 生徒機能

- **ダッシュボード**
  - 直近の授業回における自分のレコードの状態と、次に行う操作への導線を表示する。
  - 自分の達成率の推移を折れ線グラフで表示する。
  - 最新の教員フィードバックを表示する。
- **PDCA 新規追加**
  - 対象の授業回を選び、Plan 項目を 1 件以上登録して確定する。
  - 確定前の画面に、直前の授業回の Check/Act と教員フィードバックを表示する。
  - Plan 確定後、Plan 項目ごとに Do のテキストと達成状態を記録する。
  - Plan に紐づかない Do を自由記述で記録する。
  - Check/Act を入力する。
- **過去の PDCA**
  - 自分の全レコードを授業回順に一覧し、詳細を閲覧する。

### 5.4 編集とロック

- Plan は確定した時点で編集不可になる。当初の Plan を保つためである。
- Do と Check/Act は、教員フィードバックが投稿されるまで編集できる。
- 教員フィードバック投稿後、レコード全体を生徒は編集できない。
- 1 生徒につき 1 授業回に作れるレコードは 1 件とする。

### 5.5 達成率の算出

Plan 項目ごとの達成状態を点数化し、項目数で割る。

| 達成状態 | 点数 |
| --- | --- |
| 達成 | 1.0 |
| 一部達成 | 0.5 |
| 未達成 | 0.0 |

達成率 = 点数の合計 ÷ Plan 項目数 × 100（%）。
Do が未入力の項目は未達成として扱う。
Plan に紐づかない Do は達成率に含めない。

## 6. 非機能要件

- 生徒は PC（Chromebook 等）で利用する。スマートフォンでも表示が崩れない程度のレスポンシブ対応とする。
- UI は日本語のみ。
- 同時利用は 1 クラス分（数十人）を想定し、それ以上の負荷対策は行わない。
- パスワードはハッシュ化して保存する。
- 教員は全生徒のレコードを閲覧でき、生徒は自分のレコードのみ閲覧できる。

## 7. 技術選定

| 領域 | 採用 |
| --- | --- |
| フレームワーク | TanStack Start |
| 実行環境 | Cloudflare Workers |
| データベース | Cloudflare D1 |
| UI フレームワーク | shadcn/ui（Tailwind CSS） |
| 認証 | 自前の Email/パスワード認証（Cookie セッション） |

当初候補にあった Cloudflare R2 は、構造化データの一覧・集計に向かないため採用しない。
ファイル添付の要件もないため、ストレージは D1 のみとする。

UI フレームワークには shadcn/ui を使う。
コンポーネントのソースをプロジェクト内に取り込んで使う方式で、CLI で必要なものだけ追加できる。
Vite 環境をサポートしているため、TanStack Start でもそのまま導入できる。

## 8. スコープ外

- 複数教員、複数クラス、年度切り替え
- パスワードリセットメール、招待メール
- 成果物ファイルの添付
- 主体性評価などの数値評価
- CSV エクスポート
- 通知機能
